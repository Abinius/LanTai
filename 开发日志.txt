4. M1 内核 MVP：采集→台账（commit 4013393）
================================================================

pipeline/ 13 文件：
  run.py            编排器（argparse --from/--to 或 --days，串 p1→p3）
  config.py         信源注册表 + LLM 凭证读取（llm key.txt 或 LANTAI_LLM_KEY）
  contracts.py      RawItem / DataPoint / Ledger 等 dataclass
  llm.py            sensenova 客户端（stdlib urllib，thinking:disabled，退避 3 次）
  modules/p1_interval.py
  modules/p2_collect/{base.py, xwlb.py, rmrb.py}
  modules/p3_extract.py
  prompts/extract.md

设计要点：
  · 模块间只传结构化 dataclass，任一步可独立替换/重跑
  · 采集零依赖：全 stdlib（urllib.request + html.parser.HTMLParser + re）
  · base.py 容错：记录 HTTP 状态码 + 字节数 + 选择器匹配数到 run.log；
    连续 3 个 404 停止翻版
  · p3 限流降级：LLM 失败时正则命中片段仍入台账，标 llm_unverified=true，
    不阻断流水线

验收（单日 2026-10-05）：
  xwlb  1 条，published_at=2026-10-05 19:00:00（真实播出时间，非抓取时间），
        body=496 字（brief 提要）
  rmrb  37 篇，8 个版面，page 9-11 连续 404 自动停
  ledger  4-10 个数据点，**人工核对原文全部命中**：
          "3.4%" / "5.3%" / "196.3" / "348.3" / "78个步行街" 全在
          content_30184222.html 正文中 → 无 LLM 幻觉

验收（5 天 2026-10-01~05，含后续里程碑重跑）：
  189 raw（5 xwlb + 184 rmrb），49 台账点，全部 llm_unverified=false

5. M2 研判：三维交叉（commit 917069a）
================================================================

新增：
  modules/p4_analyze.py    三维交叉研判
  prompts/analyze.md       研判分析师角色 + 红线
  contracts.py             加 Analysis / Prediction
  run.py                   接入 P4，加 --reanalyze

三维交叉方法（PRD §3.4）：
  1 数据说什么——哪些强、哪些弱、矛盾在哪
  2 官媒说什么——主线、措辞升级、政策指向
  3 两者是否同频——印证 or 背离（背离处即机会/风险）

LLM 输入压缩（控成本）：
  数据面 = 台账点（indicator/value/yoy/agency + source_url）
  官媒面 = 联播提要全文（已精简）+ 人民日报标题清单（不送正文）
  输出 = core_judgments / structural_findings / predictions[{text, data_refs}]

红线（prompts/analyze.md）：
  · predictions ≥5 条，每条必须引用台账里至少一个 source_url
  · 不可编造数据；台账里没有的数字不能出现在预测里
  · 背离优先（这是判断的价值所在）
  · core_judgments ≤3 条，少而准
  · 措辞克制：用"数据显示""官媒主线指向""存在背离"，不用"必将""暴涨"

验收（5 天数据）：
  3 核心矛盾判断 + 5-6 结构性发现 + 7-10 条趋势预测，每条带可溯源 source_url
  样例（背离心发现）：
    "2500亿超长期特别国债已全额下达，但社零仅2.5%、公路流动-1.1%，
     政策投放与实物消费背离延续风险"

6. M3 出刊引擎：模板驱动深度报告（commit d63c88c）
================================================================

新增：
  modules/p5_publish.py          模板渲染 + 变量注入
  templates/report-template.md   报告骨架（{{var}} 占位）
  prompts/publish.md             出刊主编角色
  contracts.py                   加 Report
  config.py                      加 TEMPLATES_DIR
  run.py                         接入 P5，产出 report.md + report.json

★ 关键设计取舍：数据表与源列表**程序化渲染**，不走 LLM
  · 数字从 ledger 确定性生成 → 报告里没有一个数字可能被幻觉
  · 只有"标题 + 核心摘要"走 LLM 短调用（max_tokens=800），失败时程序化兜底
    （标题取首条判断前 25 字，摘要拼前两条结构性发现）
  · report.md 是文件交付物；Laravel 站不解析它，改读结构化 JSON，
    避免多一套渲染链路

报告结构（PRD §6）：
  核心摘要 / 一 核心矛盾判断 / 二 结构性发现 / 三 趋势预测（带数据支撑）
  附 数据台账 / 附 数据溯源 / 口径说明（区分"表述"与"事实"）

验收（5 天数据）：
  10693 字报告，12 个去重数据源，每条论断可溯源
  标题示例："服务业扩能与社零偏冷的张力和分化：2026国庆周观察"

7. 承自 AIHOT 时代的踩雷（v3.0 已落地为代码）
================================================================

以下四条在旧 AIHOT 开发日志里，v3.0 重构时没有忘掉，都已写进代码：

雷1 RSS/聚合源可能是死快照
  旧事：新华社 RSS 冻结在 2022-12-14，300 篇全是老稿，无 <pubDate>，
        AIHOT 用 discovered_at 冒充 published_at → 首页 2021 老稿像当天新闻
  v3.0 落地：
    · xwlb 用 CNTV API 的 time 字段作 published_at（真实播出时间）
    · rmrb 日期从 URL 路径 YYYYMM/DD 取，不用抓取时间
    · 任何一处都不做"用抓取时间回填发布日期"

雷5 sensenova 必须 disable thinking
  旧事：不加 thinking:disabled，max_tokens 全花在 reasoning 上，
        finish_reason="length"，content 为空
  v3.0 落地：pipeline/llm.py 里 "thinking": {"type":"disabled"} 硬编码进
        请求 body，所有 LLM 调用自动生效，不需要调用方记得

雷9 时效性红线（旧时代最严重的事故）
  旧事：用 timeline_at（抓取时间）批量回填 published_at，让 9 月 8 日印发的
        文件显示成"今天发布"，绕过了引擎"backfill 无真实日期不上精选"的保护
  v3.0 落地：
    · contracts.DataPoint.pub_date 解析不出就留 None（不留假值）
    · prompts/extract.md 明文写红线：pub_date 必须真实，禁止用"今天"或
      抓取日期冒充；解析不出填 null
    · 站端口径说明区也写死："未核验点为模型抽取失败时的正则命中片段，
      已单独标记，请谨慎引用"

雷4 "curl 抓到" ≠ "程序抓到"
  旧事：阿里云 WAF 对 UA 差异化处理，curl 到 72KB HTML 而引擎报 no items matched
  v3.0 落地：base.py 每次请求都记录 HTTP 状态码 + 字节数 + 选择器匹配数到
        run.log，便于诊断"到底有没有抓到"

8. v3.0 新增踩雷
================================================================

🚨 雷 A：人民日报路径迁移（会导致整源全 404）
  旧路径 rmrb/html/YYYY-MM/DD/nbs.D110000renmrb_*.htm 已 404。
  照抄历史文档/旧代码会整个源静默失效。
  新路径见第 3 节。
  教训：信源站点结构会变，路径要定期探测；探测结果要写进日志而不是只靠记。

🚨 雷 B：argparse 的 dest 与 flag 名不一致
  --from/--to 里 from 是 Python 关键字，dest 必须显式给 "from_"，
  但 --to 没指定 dest 时属性名就是 "to" 而不是 "to_"。
  两种命名混用时极易写错，直接 AttributeError。

🚨 雷 C：python 脚本导入路径
  `python pipeline/run.py` 时 sys.path[0] 是 pipeline/ 而**不是** repo root，
  `import pipeline.xxx` 会失败。run.py 里手动 insert repo root 到 sys.path；
  config.py 的信源注册表路径要写全 `pipeline.modules.p2_collect.xwlb.XwlbCollector`。

🚨 雷 D：Windows 控制台 cp936 乱码
  run.py 输出中文全乱码，但落盘文件都是正常 UTF-8。
  修：run.py 开头 sys.stdout.reconfigure(encoding="utf-8")。
  注意：`python -c "..."` 交互调试不走这段代码，仍然乱码（无害，但要看懂）。
  读 UTF-8 文件时记得同样 reconfigure，否则 print 出来是乱码、以为数据坏了。

🚨 雷 E：optimize-autoloader:true 固化 classmap（M4 最坑的一个）
  Signify 的 composer.json 配了 optimize-autoloader:true。
  删掉 app/Providers/AuthServiceProvider.php 后 artisan 全线报
    "Class App\Providers\AuthServiceProvider not found"
  原因是它被显式登记在**两个地方**：
    · bootstrap/providers.php
    · config/app.php 的 'providers' 数组
  两个都改了 + php composer.phar dump-autoload + 清 bootstrap/cache/
  才恢复。
  教训：删/加 app/Providers/*.php 后必须重生成 autoload。

🚨 雷 F：Tailwind 颜色令牌是嵌套对象
  tailwind.config.js 里是 status: { warning: '#A8791E' }
  所以类名是 bg-status-warning/5，**不是** bg-warning/5。
  写错时不报错，只是样式不生效，很难发现。

🚨 雷 G：改了 Blade 视图必须重建 CSS
  Tailwind 构建时按源码扫描生成工具类，新加视图里的类不在已编译产物里。
  本机无 node_modules（Signify 只提交了编译产物），需先 npm install
  再 npm run build:css。改视图后忘建 = 页面样式静默丢失。

🚨 雷 H：Git Bash 的 locale 是空的，中文传 curl 会被破坏
  locale= 时 `curl "http://x/?q=服务业"` 传出的字节不是标准 UTF-8，
  后端检索误报 0 命中（看起来像检索功能坏了）。
  用显式百分号编码（?q=%E6%9C%8D%E5%8A%A1%E4%B8%9A）或 PHP 侧 rawurlencode
  复现正确行为。踩过一次，排查了很久才发现是 shell 编码问题。

🚨 雷 I：php artisan serve 用 pkill 杀不掉
  Windows 下 pkill -f "artisan serve" 无效，端口仍 LISTENING。
  正确做法：netstat -ano 找端口 PID，taskkill //PID <pid> //F
  （注意 taskkill 在 Git Bash 里要写 //PID //F 双斜杠）

🚨 雷 J：LLM 输出有随机性，别把预测条数当稳定性指标
  同一批 49 个台账点重跑 P4，predictions 从 7 条变 10 条，findings 从 6 变 5。
  内容质量稳定但条数浮动。验收看"是否 ≥5 且每条带 source_url"，不看固定条数。

🚨 雷 K：dataclass 加必填字段会连带打挂兜底构造
  Report 加必填 summary 后，run.py 里出刊失败的兜底
  Report(period=..., title=..., content_md="") 直接 TypeError。
  改契约时全仓搜构造点，别只改主路径。

🚨 雷 L：composer 的 post-autoload-dump 会跑 artisan package:discover
  如果 app 起不来（比如雷 E 未修），dump-autoload 也失败，
  看起来像"composer 有问题"，其实是应用启动失败。
  报错要往上看第一行异常，不是看 composer 的退出码。
