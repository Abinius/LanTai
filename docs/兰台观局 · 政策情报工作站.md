# 第一篇 · 产品需求文档（PRD）

## 1. 概述

### 1.1 项目定位

一个**面向决策者的政策情报工作站**：以**国家官媒（人民日报 + 新闻联播）+ 官方宏观数据**为精锐信源，经"采集 → 抽取 → 三维交叉研判 → 出刊"五阶段流水线，产出**少而准的政策判断**。

> 与 AIHOT 的根本区别：**不追热点之"多"，只求判断之"准"。**

## 3. 功能需求

### 3.1 信源管理（精锐版）

* **核心信源**：人民日报（电子版）、新闻联播（文字稿）。
* **宏观核验源**：国家统计局、中国人民银行、海关总署、国家能源局、财政部、国家税务总局。
* 信源类型：网页版面列表、网页条目、**宏观口径核验**。
* 分级门槛：核心信源必采；核验源按需调用。
* 后台：试抓、诊断、启停、结构变更告警。

### 3.2 采集（P2）

* 定时抓取（cron 触发，按区间）。
* 人民日报：版面页 → 文章清单（标题 + 链接）；**按需抓正文**。
* 新闻联播：条目 → 文字稿全文。
* 容错：连续 3 个 404 停止；某日 0 篇即告警重试。

### 3.3 抽取（P3）

* 从官媒文本抽取全部量化数据点（增长/投资/消费/外贸/物价/金融/能源/财政/就业）。
* 记录：**指标名 / 数值 / 口径 / 同比环比 / 发布机构 / 日期**。
* 联网核验权威口径，警惕二手转述与往年混淆。
* 产出：按主题分组的"**数据台账**"。

### 3.4 三维交叉研判（P4 · ★核心）

把三条线叠在一起：

1. **数据说什么**——哪些强、哪些弱、矛盾在哪。
2. **官媒说什么**——主线、措辞升级、政策指向。
3. **两者是否同频**——印证 or 背离（背离处即机会/风险）。

* 输出：核心矛盾判断、结构性发现、≥5 条带数据支撑的趋势预测。

### 3.5 出刊（P5 · 借 AIHOT 出刊引擎范式）

| **周期** | **产物**          |
| ------ | --------------- |
| 日      | 政策信号速览（可选）      |
| 周      | 政策信号周报（可选）      |
| **月**  | **深度研判月报（主产物）** |
| 专题     | 聚焦式专项分析（复用已采数据） |

### 3.6 检索与主题

* 全文检索；主题页（政策主题 / 地区 / 指标）。

### 3.7 后台管理

* 信源管理、诊断、评测；每步可换模型；**预算熔断**；运行记录与告警。

### 3.8 Agent 接入

* 提供 API / MCP / RSS / llms.txt，供 AI Agent 调用。

### 3.9 订阅端（第二阶段 · Signify）

* 用户设"兴趣标签"（领域 × 地区）。
* 情报按标签匹配 → 摘要卡片 → 推送到"我的情报"。

# 第二篇 · 产品开发文档（零 Docker）

## 1. 技术架构

```
┌──────────────────────────────────────────────┐
│  接入层  Nginx（反代 + 静态 + HTTPS）           │
├──────────────────────────────────────────────┤
│  应用层                                          │
│   ① Laravel 站（兰台观局 UI = Signify 风格）    │
│   ② Python 内核（月度监测五阶段流水线）          │
├──────────────────────────────────────────────┤
│  数据层  MySQL（对齐 Signify）                   │
├──────────────────────────────────────────────┤
│  进程层  cron（内核）+ systemd（服务）           │
└──────────────────────────────────────────────┘
```

**核心思路**：

* **内核是 Python 批处理**（月度监测五阶段），**不是常驻 Node 服务**——更轻。
* **Laravel 站读取内核产出的报告/数据**渲染（Signify 风格）。
* **统一 MySQL**（与 Signify 同库同栈，未来集成零摩擦）。
* **零 Docker**：Python + PHP-FPM + Nginx + MySQL + cron。

> **架构红利**：去掉 Node 引擎与 pg-boss 后，**依赖大幅减少，MVP 更快**。

## 2. 技术栈选型（零 Docker）

| **层**   | **选型**                                        | **说明**                  |
| ------- | --------------------------------------------- | ----------------------- |
| OS      | **Linux**（Ubuntu 22.04 / CentOS 7+）           | 服务器                     |
| Web 服务器 | **Nginx**                                     | 反代 + HTTPS + 静态         |
| 前端站     | **Laravel 11 + Blade + Alpine.js + Tailwind** | **Signify 同款**          |
| **内核**  | **Python 3.12（标准库为主）**                        | 五阶段流水线，**采集零依赖**        |
| LLM     | 任意兼容 API（分级）                                  | 抽取/研判/写作                |
| 检索      | web search API                                | 宏观口径核验                  |
| 数据库     | **MySQL 5.7+**                                | 对齐 Signify              |
| 调度      | **cron**                                      | 定时触发内核                  |
| 进程守护    | **systemd**                                   | PHP-FPM / Nginx / MySQL |
| 缓存      | Redis（可选）                                     | 提升性能                    |

## 3. 模块化流水线设计（★借 AIHOT 范式）

```
input(区间)
  │
  ▼
[P1] interval    解析区间 → YYYYMMDD
  ▼
[P2] collect     采集模块（适配器：rmrb / xwlb）
  ▼
[P3] extract     抽取模块（预处理正则 + LLM 结构化 + 核验）
  ▼
[P4] analyze     研判模块（三维交叉 · LLM）
  ▼
[P5] publish     出刊模块（模板渲染 → md/HTML）
  ▼
output(报告 + 数据台账)
```

**模块契约（借 AIHOT 的"每步可替换"设计）**：

| **模块**  | **输入**    | **输出**             | **可替换** |
| ------- | --------- | ------------------ | ------- |
| collect | 区间        | 原始 JSON（rmrb/xwlb） | 适配器化    |
| extract | 原始 JSON   | 数据台账（JSON）         | 换模型/脚本  |
| analyze | 台账 + 官媒文本 | 研判结构（JSON）         | 换模型/提示词 |
| publish | 研判结构      | 报告 md/HTML         | 换模板     |

> 原则：**模块之间只传结构化数据**，任一步可独立替换/重跑。

## 4. 出刊引擎（★借 AIHOT 范式）

* **模板驱动**：`report-template.md` 为骨架，变量注入。
* **多周期**：日/周/月/专题，共用引擎。
* **多格式**：Markdown（主）→ HTML/PDF（可选）。
* **交付**：生成后 `provide_file` + 归档知识库。
* **复用**：聚焦式改写复用已采数据，不重复抓取。

### 5.6 设计纪律

1. 留白优先——宁可少放，不要塞满。
2. 衬线管标题、无衬线管正文——层级靠字体不靠颜色。
3. accent 是"印章"——全页 \<5%，只点关键。
4. 直角（2px）+ 细线（hairline）——刊物感两根支柱。
5. 不堆卡片阴影——唯一浮层用 `shadow.float`。
6. 动效极轻——仅 hover 变色与图片微缩放（200–500ms）。

> **收益**：UI 与 Signify 同源 → 品牌差异靠内容体现 → 未来在 Signify 开订阅板块时**零视觉割裂**。

```bash
sudo apt install -y nginx mysql-server php8.2-fpm php8.2-{cli,mysql,mbstring,xml,curl,zip,bcmath,gd}
sudo apt install -y python3 python3-pip

# 采集脚本零第三方依赖，无需 pip 包
```

## 7. 部署步骤（零 Docker）

```
① 数据库：MySQL 建库 laotai / 建用户 → 授权
② Laravel 站（兰台观局 · Signify 风格）：
   git clone <兰台观局> /www/laotai
   composer install --no-dev
   cp .env.example .env && php artisan key:generate
   配置 .env（DB / 内核产物路径）
   php artisan migrate && php artisan config:cache
③ Python 内核（月度监测）：
   git clone <月度监测内核> /www/laotai-kernel
   （纯标准库，无需装依赖）
④ 调度：cron 定时跑内核（如每月 1 日）
   0 8 1 * * python3 /www/laotai-kernel/run.py --days 30
⑤ 进程守护：Nginx / PHP-FPM / MySQL 用 systemd（系统原生）
⑥ Nginx：反代 Laravel（/），静态资源直出
```

## 11. 开发计划（里程碑）

| **阶段**          | **内容**                  | **交付**       |
| --------------- | ----------------------- | ------------ |
| **M1 · 内核 MVP** | 采集增强（正文）+ 编排器骨架         | 一键"采集→台账"    |
| **M2 · 研判**     | 抽取脚本 + 研判提示词 v1         | 自动生成首份月报     |
| **M3 · 出刊引擎**   | 模板化出刊 + 多周期             | 稳定产出 md/HTML |
| **M4 · 前端**     | Laravel 站（Signify 风格）   | 可视化站点上线      |
| **M5 · 集成**     | Signify 订阅板块（兴趣标签 + 摘要） | 企业家订阅        |

## 12. 风险与对策

| **风险**              | **对策**                  |
| ------------------- | ----------------------- |
| **LLM 幻觉**（编数据/机构名） | 论断回原文核对；数字可溯源；机构名白名单    |
| 官网结构变更              | 告警 + 适配器化 + 重试          |
| **版权/合规**           | 先内部自用；对外评估授权；只做"研判+链接"  |
| LLM 成本              | 分级模型 + 预处理压缩 + 预算熔断     |
| 研判质量下限              | MVP 核心验证点；few-shot + 抽检 |
| 人民日报正文缺失            | 补 `fetch_article()`，按需抓 |
